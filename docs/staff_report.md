# スタッフ業務報告

## 使い方
- 職員：ポータルの「法人共通」→「今日の業務報告・私のToDo」（#report）。「問題なし」を1回押すか、1行書いて送る。困りごとは任意。自分のToDoは画面の下に出て、未着手／進行中／完了を直せる（動かすと更新日時が変わる）。
- 管理者（事務・管理者・児発管）：「事務」→「人事労務」→「業務報告（朝の確認）」（#report/admin）。1画面に、今日まだ報告がない人／動いていないToDo（3日以上動きなし・期限切れ）／困りごと（直近7日）／今日の報告一覧。ToDoもここから出す。
- 報告対象の人：`update staff_profiles set daily_report = true where full_name = '○○';`（名前はリポジトリに書かない）。
- 日数の変更：report.js の `SR.staleDays`。

## 秘書の朝まとめ（毎朝7:23）の切り替え方
いまは報告が0件のあいだ、秘書は何も送っていません。ポータルが動き出してからの選択肢は2つです。
1. 止める（いちばん簡単）：秘書の朝まとめの実行を止め、齊藤さんは朝にポータルの「業務報告（朝の確認）」を1回見る。Google Chatは通知のため残すので、「報告がない人がいたらChatに1行」だけ別に足してもよい。
2. ポータルの内容を読む形にする：秘書が毎朝、データベースの staff_report / staff_todo を読んで、いまの朝まとめに「報告がない人・動いていないToDo・困りごと」を足す。読み取り専用の鍵（service_role は使わず、読むだけの方法）を用意する。
おすすめは、まず1週間、両方を並べて動かして内容が合うか見てから、1で止める流れです。通知はまだ何も始めていません。

## 他の事業所へ
名簿は staff_profiles から取るので名前は不要。daily_report を立てた人だけが対象。supabase/staff_report.sql を流すだけで使える。
