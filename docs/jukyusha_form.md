# 受給者証の入力フォーム（保護者 → 職員の確認 → 利用者情報）

写真は受け取りません（連先生の確認どおり）。保護者が、広げた受給者証を見ながら項目を入力し、職員が確認して反映します。
OCR・写真・Storage（保管場所）はありません。

## 流れ
1. 職員：ポータル **レオ → 受給者証の入力（保護者から）** で児童を選び「リンクをコピー」。専用リンクができます（30日有効）。
2. 職員：リンクを公式LINEの1対1トークに**手で**貼って送る（自動では送りません）。
3. 保護者：リンクを開き、広げた受給者証を見ながら入力（①〜⑤の面の見本の図つき）→「入力内容を確認する」→ 確認画面 →「この内容で送る」。
   同意（利用目的）にチェックしないと進めません。
4. 職員：一覧の「確認」を開くと、保護者の入力と**いまの利用者情報**が並びます。違うところに色がつき、チェックが入ります。値は直せます。
5. 職員：「確認して反映」→ 確認ダイアログ（いまの値 → 新しい値）→ OK で、チェックした項目だけ利用者情報に書き込み。**前の値は記録に残ります。**
   「反映しない」でメモだけ残して終わることもできます。

反映のボタンを押すまで、利用者情報は一切変わりません。

## 連先生・Reo が実行する SQL
Supabase の SQL Editor で `supabase/leo_jukyusha_form.sql` を**1回**実行（再実行しても壊れません）。
新しい表 `leo_jf_links` `leo_jf_subs` と関数 `leo_jf_*` を作るだけで、既存の表・データには触りません。Storage は使いません。
（以前の OCR 版の `leo_jk_*` は本番では実行していないので、そのまま不要です。）

給付決定期間のはじめは、請求用の「契約開始日」(contract_start) とは別物なので反映しません。

## 日付
令和・平成・西暦のどれでも入力でき、その場で西暦を表示して確認できます。令和は2019-05-01から、平成は1989-01-08〜2019-04-30として、実在する日付かも確認します（`jukyusha_lib.js`、サーバー側でも検証）。

## 個人情報の扱い
- 入力の画面に利用目的（利用者負担額・支給量の確認と請求の手続き）と取り扱いの説明を出し、同意のチェックが必要。送信時に同意の日時を記録。
- 保護者の画面からは、利用者情報（住所など）は一切読めません。リンクで分かるのは児童名と「送信ずみか」だけ。
- 表は職員（`can_manage()`）だけが読めます。書き込みはすべて関数（RPC）経由。1時間に5回までの送信制限。
- 入力の記録（leo_jf_subs）には個人情報が残ります。保管期間・削除のしかたは未決定（下の質問）。

## テスト（架空データのみ）
- `node tools/jukyusha_form_check.js` … 日付・番号などの検証（lib）
- `cd tools && node jukyusha_form_sql_test.mjs` … PGlite で SQL（権限・検証・反映・前の値・再実行）。`@electric-sql/pglite` が必要。
- `node tools/jukyusha_form_ui_test.js` … ブラウザ（puppeteer-core）で保護者ページ（スマホ幅）と職員画面。`python3 -m http.server 8099` をリポジトリ直下で起動し、`OUT=/tmp/jf/` を付けるとスクリーンショットも保存。Supabase への通信はすべて差し替え。
