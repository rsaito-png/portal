# 受給者証の入力フォーム（保護者 → 職員の確認 → 利用者情報）

写真は受け取りません（連先生の確認どおり）。保護者が、広げた受給者証を見ながら項目を入力し、職員が確認して反映します。
OCR・写真・Storage（保管場所）はありません。

## 流れ
1. 職員：ポータル **レオ → 受給者証の入力（保護者から）** で児童を選び「リンクをコピー」。専用リンクができます（30日有効）。
   2回め以降は「**前回の内容を入れておく**」（下の「2回めからの入力」）。
2. 職員：リンクを公式LINEの1対1トークに**手で**貼って送る（自動では送りません）。
3. 保護者：リンクを開き、広げた受給者証を見ながら入力（①〜⑤の面の見本の図つき）→「入力内容を確認する」→ 確認画面 →「この内容で送る」。
   同意（利用目的）にチェックしないと進めません。
4. 職員：一覧の「確認」を開くと、保護者の入力と**いまの利用者情報**が並びます。違うところに色がつき、チェックが入ります。値は直せます。
5. 職員：「確認して反映」→ 確認ダイアログ（いまの値 → 新しい値）→ OK で、チェックした項目だけ利用者情報に書き込み。**前の値は記録に残ります。**
   「反映しない」で記録だけ残して終わることもできます。

反映のボタンを押すまで、利用者情報は一切変わりません。

## 連先生・Reo が実行する SQL
Supabase の SQL Editor で `supabase/leo_jukyusha_form.sql` を**1回**実行（再実行しても壊れません）。
新しい表 `leo_jf_links` `leo_jf_subs` と関数 `leo_jf_*` を作ります。既存の表には**列を足すだけ**（`leo_child_info.soudan_office` / `soudan_person`、`add column if not exists`）で、既存のデータは変えません。Storage は使いません。
`leo_jf_make_link` は引数が増えたので、古い版（引数1つ）を `drop function if exists` してから作りなおします（再実行しても同じ）。
**SQL を実行する前に、新しい画面だけを先に出すと**、利用者情報の相談支援の欄は出ません（列がないため。保存が失敗しないよう、列があるときだけ出します）。
（以前の OCR 版の `leo_jk_*` は本番では実行していないので、そのまま不要です。）

## 2回めからの入力（前回の内容を入れておく）
2回め以降は、全部を打ち直さなくていいように、リンクを作るときに「**前回の内容を入れておく**」を選べます。
- 職員のリンク作成：児童を選ぶと、前の入力（反映ずみ）か、利用者情報に受給者証番号があるときは、自動でチェックが入ります（はずせます）。ないときは空の入力ページ。
- 保護者のページ：前回の内容が入った状態で開き、「前回の内容が入っています。変わったところだけ直してください（多くは有効期間です）」と出ます。**給付決定期間（はじめ・終わり）の2か所は色がついて**注意が出ます。確認画面では、前回から直した項目に「前回から変更」が付きます。
- 入る内容：①いちばん新しい**反映ずみ**の入力（相談支援・支給量等の文字・その他などの参考欄も）に、②いまの**利用者情報**（受給者証番号・市町村番号・サービス・支給量・契約終了日・負担上限・無償化・保護者名・相談支援）を重ねたもの。**利用者情報が優先**です。反映前の入力は使いません。
- 送ったあとの職員の確認は今までどおり。**いまの利用者情報と違う項目だけ**にチェックが入るので、期間だけ変わったときは「給付決定期間（終わり）」の1行だけになります。
- 仕組み（`leo_jf_get`）：prefill は、職員が「入れておく」で作ったリンクで、期限切れ・取り消しでないときだけ返ります。返すのは決まった19項目だけ（上のテストで確認）。**備考・住所・電話・ほかの児童の情報は返しません**。リンクはその1人の児童だけ、期限は今までどおり30日。
- **注意（個人情報）**：このリンクを開いた人には、お子さんのお名前・受給者証番号・保護者名・相談支援事業所名・担当者名などが**そのまま見えます**。リンクは、その家庭の保護者の1対1のLINEにだけ送ってください。ほかの人に転送されると見えてしまいます。心配なときは「入れておく」をはずして作りなおします（同じリンクのまま空の入力ページに戻り、期限も延びます）。リンクを取り消す機能は SQL のみ（`leo_jf_links.revoked`）。

## 日付
令和・平成・西暦のどれでも入力でき、その場で西暦を表示して確認できます。令和は2019-05-01から、平成は1989-01-08〜2019-04-30として、実在する日付かも確認します（`jukyusha_lib.js`、サーバー側でも検証）。

## 個人情報の扱い
- 入力の画面に利用目的（利用者負担額・支給量の確認と請求の手続き）と取り扱いの説明を出し、同意のチェックが必要。送信時に同意の日時を記録。
- 保護者への説明は「職員が確認してから反映する。必要に応じて、受給者証の原本を見せていただくことがある」。職員が受給者証（写真）と見くらべる、とは書かない。
- 保護者の画面からは、利用者情報（住所など）は読めません。リンクで分かるのは児童名と「送信ずみか」だけ。**ただし「前回の内容を入れておく」で作ったリンクは別で、決まった項目（上の「2回めからの入力」）が見えます。**
- 表は職員（`can_manage()`）だけが読めます。書き込みはすべて関数（RPC）経由。1時間に5回までの送信制限。
- 入力の記録（leo_jf_subs）には個人情報が残ります。保管期間・削除のしかたは未決定（下の質問）。

## テスト（架空データのみ）
- `node tools/jukyusha_form_check.js` … 日付・番号などの検証（lib）
- `cd tools && node jukyusha_form_sql_test.mjs` … PGlite で SQL（権限・検証・反映・前の値・再実行）。`@electric-sql/pglite` が必要。
- `node tools/jukyusha_form_ui_test.js` … ブラウザ（puppeteer-core）で保護者ページ（スマホ幅）と職員画面。`python3 -m http.server 8099` をリポジトリ直下で起動し、`OUT=/tmp/jf/` を付けるとスクリーンショットも保存。Supabase への通信はすべて差し替え。
